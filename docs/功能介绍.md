# 背备不悲 · 功能介绍

> **背**得会 · **备**得全 · **考**不悲
>
> 一个本地部署的 AI 学习工具：把资料变成题库，把知识讲出来，把短板补上去。

---

## 它解决什么问题

传统背书有三个断点：

| 断点 | 表现 | 本工具的做法 |
|---|---|---|
| **资料进不去脑子** | 资料躺在硬盘里，看不完也记不住 | 上传即入 RAG 知识库，自动抽知识点、按知识点出题 |
| **背会了但讲不出来** | 题能刷对，一开口就卡壳 | 语音作答 / AI 模拟面试，逼你把话说完 |
| **错了不知道为什么错** | 只知道对错，不知道漏了哪个要点 | AI 按评分要点判分，标明命中/遗漏，并引用原文出处 |

一句话概括**输出侧**的价值：刷题考的是「你记不记得」，模拟面试考的是「你能不能讲清楚」——两者都要。

## ① 文档入库：Word / PDF / PPT / 照片都能进

- **多格式解析**：PDF（PyMuPDF）、Word（python-docx）、PPT、Excel、Markdown、纯文本
- **扫描件 OCR**：PDF 检测到没有文本层时自动转 PaddleOCR；照片直接 OCR
- **智能分块**：按语义边界切块（目标 700 字、重叠 105 字），保留页码与章节路径
- **混合检索**：BGE-M3 稠密向量 + Milvus 原生 BM25 稀疏向量，用 RRF 融合排序
  - 稠密向量管「意思相近」，BM25 管「关键词精确命中」，两者互补
- **进度可见**：解析是异步任务，前端通过 SSE 实时看进度（`正在向量化 45/226 块`）

> **为什么要混合检索**：纯向量检索对专有名词不敏感——搜「布隆过滤器」可能召回一堆「缓存」相关段落；纯关键词又搜不到同义表达。两者融合后，本项目实测「缓存穿透 / 缓存击穿 / 缓存雪崩」这类只差一个字的术语能准确区分。

## ② 知识点体系：让题目有归属

- AI 从资料里抽**最多 3 层**的知识点树（模块 → 考点 → 细项）
- 每个分块自动打标（最多 3 个知识点，宁少勿滥）
- 知识点上聚合题量与正确率，一眼看出哪块薄弱
- 支持手工增删改，AI 抽得不好可以自己修

## ③ AI 出题：不是「同义改写」，是真出题

- **题量**：10 / 20 / 30 / 自定义
- **题型**：单选、多选、判断、填空、名词解释、简答、论述、代码题、对比题
- **配比可调**：按题型和难度（易/中/难）设比例
- **范围可控**：指定知识点（自动包含子知识点）或整库
- **按知识点分批生成**：一次生成太多容易跑题，所以按知识点分批调用再合并
- **每道题都带溯源**：记录答案出自哪个分块，点一下能看到原文

## ④ 题目审核：AI 出的题不能直接信

这是**硬性约束**，不是可选项：

- 生成后进审核页，逐题看题干 / 答案 / 评分要点 / 溯源分块 / AI 质量分
- 可以**通过 / 编辑 / 删除 / 重新生成**
- 只有「已通过」的题才会出现在答题页
- **跨批次向量查重**：与已有题目相似度 > 0.92 直接丢弃
- AI 自检：检查「答案能否从原文推出」「有没有歧义」「选项是否自洽」

## ⑤ 语音作答：按住空格就能说

- **快捷键**：长按空格说话，松开自动识别并回填（也可切换成点按模式）
- **智能避让**：光标在输入框里时空格就是打空格；中文输入法选词时绝不抢键
- **专有名词热词纠错**：从知识库知识点构建热词表，把「缓存基础」纠回「缓存击穿」
- **长录音自动切段**：讯飞单次会话上限 60 秒，超长录音在静音处切开分别识别（切点用能量最小值找，避免把字劈成两半）
- **失败自动重试**：网络抖动不会让整段白录
- **降级不阻塞**：语音不可用时按钮自动隐藏，直接打字，不卡住答题流程

> 用不了语音也不影响任何功能——所有需要作答的地方都支持打字。

## ⑥ AI 判分：可解释、可申诉

判分策略按题型分流，**能程序判的绝不调大模型**（省钱且更稳定）：

| 题型 | 判分方式 | 是否用 AI |
|---|---|---|
| 单选 / 多选 / 判断 | 程序比对（多选支持部分得分） | 否 |
| 填空 | 归一化匹配 + 同义词表，未命中才交 AI | 部分 |
| 名词解释 / 简答 / 论述 | AI 按评分要点（rubric）打分 | 是 |
| 代码题 | AI 检查关键点 | 是 |

- **命中 / 遗漏要点高亮**：不只给分，还告诉你漏了哪一条
- **原文引用**：AI 给的判断必须能对上材料原文，对不上会标注出来
- **申诉重判**：对分数有异议可以申诉，AI 重新判一次

## ⑦⑧ 错题本 + 艾宾浩斯复习

- 判错的题自动进错题本，按 **SM-2 算法**排复习计划
- 答对间隔拉长，答错重来；难度系数动态调整
- 首页推「今日待复习」，到点提醒
- 连续答对到一定程度自动移出错题本（标记已掌握）

## ⑨ 学习统计

- 知识点掌握度**雷达图**（只显示最弱的 8 个——雷达图的目的是暴露短板，不是炫耀）
- 答题正确率趋势
- **Token 用量与成本**：按厂商、按任务类型统计，知道钱花在哪

## ⑩ AI 模拟面试（独立模块）

这是**输出侧**的能力：前面解决「把题刷对」，这里解决「把话讲清楚」。

**流程**

```
上传简历 → AI 抽结构化档案 → 面试官逐轮追问 → 五维实时评分 → 评估报告 → 薄弱点一键出题
```

**面试官怎么问**（写死在 Prompt 里的策略，避免聊成随便侃）：

1. 第 1 轮固定自我介绍
2. 之后顺着简历里的项目做深度追问：为什么这么设计、遇到什么问题、怎么解决、有没有量化结果
3. 每 3 轮穿插一道原理题，验证基础是否扎实
4. **候选人上一轮含糊（只给结论不给过程）就优先追问那个点**
5. 同一主题最多连续追问 2 轮，第 3 轮必须换话题（否则整场只覆盖一个技术点）
6. 不重复已问过的问题，一次只问一个

**每个问题都可追溯**：标注题型（自我介绍/项目深挖/原理考察/追问/场景设计/行为面）和「依据简历哪一段原话」——你随时知道面试官为什么问这个。

**五维评分**（每轮实时给分，不用等最后）：

| 维度 | 看什么 |
|---|---|
| 技术准确性 | 技术表述是否正确、有没有概念错误 |
| 项目具体性 | 有没有讲清自己做了什么、什么数据、什么取舍 |
| 表达结构 | 有没有条理（背景 → 方案 → 结果） |
| **与简历一致性** | 回答是否与简历原文矛盾，矛盾必须扣分并引用简历原话 |
| 岗位匹配度 | 是否切题、是否命中岗位核心要求 |

> **「与简历一致性」是面试模块独有的维度。**
> 学习题目的答案有原文依据，客观题能 100% 程序化判分；面试没有标准答案，
> 唯一能硬核核对的就是「你嘴上说的和简历写的是否对得上」——
> 这是模拟面试相对于「和 AI 随便聊聊」唯一不可替代的价值。
>
> 实测：简历写的是 2023–2027 在校生，测试脚本却答「两年工作经验、上一家公司」，
> 模型第 1 轮就抓到矛盾，随后连续追问 4 轮，分数从 42 掉到 12。

**评估报告**包含：总分、维度雷达、逐轮得分曲线、优势、**薄弱项（带面试中的具体证据）**、优先补的知识点、下一步建议。

**闭环联动**：报告里的知识点 → 在知识库里按名字匹配标签 → **一键生成专项题卷**，直接回到学习模块去刷。

> 简历与学习知识库**完全隔离**：不进 Milvus、不建知识点树、不参与 RAG 检索。
> 唯一的跨界通道就是上面这个「薄弱点 → 出题」。

## 工程特性（给想改代码的人看）

| 特性 | 说明 |
|---|---|
| **三端分离** | Java 网关（业务/鉴权/调度）+ Python 智能体（AI 能力）+ Vue 前端 |
| **浏览器只跟 Java 说话** | Python 只在内网被 Java 调用，前端对它的存在完全无感 |
| **AI 厂商可切换** | 统一走 OpenAI 兼容协议，DeepSeek / 通义 / 智谱 / Kimi / OpenAI 界面上一键切 |
| **Embedding 与 LLM 解耦** | 向量用本地 BGE-M3，换大模型绝不影响已入库向量（硬约束） |
| **API Key 加密存储** | AES-256-GCM，Java 加密 / Python 解密，两边算法严格对齐 |
| **Prompt 版本化** | 模板存数据库，界面可改，改完自动生成新版本，可回滚 |
| **Mock 演示模式** | 没有 API Key 也能把全链路跑通（真的从材料里抽句子出题，不是假数据） |
| **长任务走 SSE** | 解析/出题/判分/简历解析都是异步任务 + 实时进度推送 |
| **一致性校验** | MySQL 分块 ↔ Milvus 向量双向核对，一键清理孤儿向量 |

## 没有 API Key 也能玩

把 `beibei-agent/.env` 里的 `LLM_MOCK` 设成 `true`，出题 / 判分 / 面试提问都会走本地规则法：

- **真的**从你的材料里抽句子出题、从简历里抽技能提问，不是写死的假数据
- 全链路（上传 → 出题 → 审核 → 作答 → 判分 → 复习 → 面试）都能走通
- 不花一分钱

**但要说清楚它的局限**：Mock 的输出很粗浅——面试永远问「你简历里写了 X，说说怎么用的」，不会顺着你的回答追问；评分每轮都差不多（按回答长度 + 关键词命中率估算）。**它只能用来验证链路，不能用来评估自己的水平。**

配好真实 Key 后把 `LLM_MOCK` 改成 `false` 即可，见 [部署文档](部署文档.md)。

## 适用边界

**适合**

- 个人备考：软考、考研、认证考试、面试准备
- 需要背大量资料的场景：法条、医学、技术文档
- 想练「讲清楚」而不只是「选对」的人

**不适合**

- 多人协作（没有账号体系，单用户设计）
- 移动端（浏览器可用，但没有原生 App）
- 完全离线（大模型和语音需要联网；向量化与 OCR 是本地跑的）
