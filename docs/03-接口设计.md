# 背备不悲 · 接口设计

> 前端 → Java：`http://localhost:8080/api/**`（统一响应体、Sa-Token 鉴权）
> Java → Python：`http://127.0.0.1:8000/api/v1/**`（内网，`X-Internal-Token` 校验）
> 长任务统一走异步任务 + SSE 进度

---

## 1. 通用约定

### 1.1 统一响应体

```json
{ "code": 0, "msg": "ok", "data": { }, "traceId": "a1b2c3d4" }
```

`code`：0 成功；400x 参数/业务错误；401 未登录；500 服务异常；`5031` 智能体未启动。

### 1.2 分页

请求：`?pageNum=1&pageSize=20&keyword=&kbId=`
响应：`{ "total": 123, "list": [ ] }`

### 1.3 异步任务 + SSE

提交类接口返回 `taskId`：

```json
{ "code": 0, "data": { "taskId": 1001, "bizId": 55 } }
```

前端订阅：

```
GET /api/task/{taskId}/stream      Accept: text/event-stream
```

SSE 事件格式：

```
event: progress
data: {"taskId":1001,"progress":45,"stage":"正在生成第 9/20 道题","status":1}

event: done
data: {"taskId":1001,"status":2,"progress":100,"bizId":55,"summary":{"count":20,"dropped":3}}

event: error
data: {"taskId":1001,"status":3,"errorMsg":"LLM 返回格式非法，重试 3 次后失败"}
```

前端降级：SSE 不可用时轮询 `GET /api/task/{taskId}`。

### 2.6 语音转文字 `/api/asr`

```
POST /api/asr/transcribe        Content-Type: multipart/form-data
  audio: <webm/opus 或 wav 文件>
  language: zh_cn
  domain: exam_answer            // 领域热词，喂给 ASR 提升专有名词准确率
→ { "text": "缓存穿透是指查询一个一定不存在的数据", "durationMs": 3200, "provider": "xfyun" }
```

**设计要点**
- 前端 `MediaRecorder` 默认 `audio/webm;codecs=opus`，Java 转 Python 后由 ffmpeg 转 16k 单声道 PCM 再送云端 ASR。
- 传 `domain=exam_answer` 时，Python 侧把当前知识库的高频专有名词（Redis、Spring Cloud、MyBatis…）拼进 ASR 的**热词表**，显著降低专有名词错字率。这是本产品的关键细节。
- 单次录音限制 60s，超时前端自动分片。
- ASR 不可用时返回 `code=5032`，前端把输入框保留为空并提示"语音暂不可用，请手动输入"，**不阻塞作答**。

**面试对话**（除解析外都是同步的：一轮 = 一次 LLM 调用）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/interview/start` | `{resumeId, jobTitle?, kbId?, difficulty?, maxTurns?}` → 第一题 |
| POST | `/api/interview/{id}/answer` | `{answer}` → `{evaluation, nextQuestion, finished}` |
| POST | `/api/interview/{id}/finish` | 生成评估报告 → 面试详情 |
| GET | `/api/interview/list` | 面试场次列表 |
| GET | `/api/interview/{id}` | 详情：`{interview, turns, report}` |
| DELETE | `/api/interview/{id}` | 删除场次 |
| POST | `/api/interview/{id}/linkage-paper` | `{kbId?, tagIds?, count?, selfCheck?}` → `{paperId, taskId, matchedTags, unmatchedPoints, matches, message}` |

`finished: true` 表示轮数用完（`nextQuestion` 为 `null`），前端应引导用户去出报告。

`linkage-paper` 是面试模块与学习模块**唯一的连接点**：
拿报告里的 `knowledgePoints` 去 `bb_tag` 按名字做**双向包含**匹配
（报告说「Redis 缓存穿透」、知识库里叫「缓存穿透」也算命中，因为大模型给的名字
和人工建的标签粒度天然对不齐），匹配不到就退化成整库出题并在 `message` 里说明。

两条容易踩的细则：

1. **匹配前会先剥掉层级后缀**（`篇 / 章 / 节 / 模块 / 部分 / 专题 / 系列 / 基础 / 入门 / 详解`）。
   真实模型生成的标签树就长这样：`MySQL篇`、`Redis篇`；不剥的话知识点 `MySQL` 永远匹配不上。
2. **只拿「有分块」的知识点当候选**（`chunk_count > 0`）。
   零分块的标签底下一块原文都没有，匹配上它出题时一块材料都取不到，等于白匹配。
   如果整个知识库的标签分块数都没统计过（全为 0），才退回用全部标签。

`matches` 是排查匹配结果用的，形如：

```json
[{"point": "JVM内存排查", "tagName": "JVM内存排查", "tagId": 369, "chunkCount": 1},
 {"point": "布隆过滤器",  "tagName": "布隆过滤器篇", "tagId": 370, "chunkCount": 1}]
```

### 3.1 出题接口契约

```json
POST /api/v1/generate-questions   (SSE)
{
  "taskId": 1001,
  "kbId": 1,
  "collection": "bb_chunk_bge_m3",
  "partition": "kb_1",
  "count": 20,
  "tagIds": [12, 13],
  "includeChildTags": true,
  "qTypeRatio": { "SINGLE": 0.4, "MULTI": 0.2, "JUDGE": 0.1, "BLANK": 0.1, "SHORT": 0.2 },
  "difficultyRatio": { "EASY": 0.3, "MEDIUM": 0.5, "HARD": 0.2 },
  "providerId": 3,
  "paperId": 55
}
```

Python 侧流水线：

```
① 按知识点分组，按 qTypeRatio/difficultyRatio 分配各组题量
② 每组用知识点名做 query 检索 top-k 分块（k=8），拼 prompt
③ LLM 出题 → Pydantic 强校验 JSON Schema → 失败重试 ≤3
④ 自检 Agent：题干+答案能否被召回分块支撑？不通过则丢弃并补生成
⑤ 查重：与 bb_question 已有题向量比对，相似度 > 0.92 丢弃
⑥ 落库 bb_question(status=DRAFT) + options + tags + paper_item
⑦ SSE 每完成一道推一次 progress
```

**LLM 必须返回的 JSON 结构（强约束）**

```json
{
  "questions": [
    {
      "qType": "SINGLE",
      "difficulty": 2,
      "stem": "下列关于 Redis 缓存穿透的说法，正确的是？",
      "options": [
        { "key": "A", "content": "..." },
        { "key": "B", "content": "..." }
      ],
      "answer": "B",
      "analysis": "缓存穿透指查询不存在的数据……",
      "rubric": null,
      "tagIds": [12],
      "sourceChunkIds": [5521, 5522]
    },
    {
      "qType": "SHORT",
      "difficulty": 3,
      "stem": "简述 Redis 缓存击穿的成因与解决方案。",
      "options": null,
      "answer": "成因：热点 key 在失效瞬间……方案：互斥锁、逻辑过期……",
      "analysis": "该考点在讲义 5.3 节，属于高频面试题。",
      "rubric": [
        { "point": "说出成因是单个热点 key 失效", "score": 3 },
        { "point": "答出互斥锁方案", "score": 3 },
        { "point": "答出逻辑过期方案", "score": 2 },
        { "point": "提到不设置过期时间或提前预热", "score": 2 }
      ],
      "tagIds": [12],
      "sourceChunkIds": [5521]
    }
  ]
}
```

### 3.2 判分接口契约

```json
POST /api/v1/grade   (SSE)
{
  "taskId": 1002,
  "examId": 88,
  "providerId": 3,
  "items": [
    {
      "answerItemId": 9001,
      "questionId": 301,
      "qType": "SHORT",
      "stem": "简述 Redis 缓存击穿的成因与解决方案。",
      "referenceAnswer": "成因：……方案：互斥锁、逻辑过期……",
      "rubric": [ { "point": "说出成因是单个热点 key 失效", "score": 3 } ],
      "userAnswer": "击穿是热点 key 过期……",
      "sourceChunks": [ { "chunkId": 5521, "content": "缓存击穿是指……", "pageNo": 88, "sectionPath": "第5章 > 5.3" } ],
      "fullScore": 10
    }
  ]
}
```

Python 侧：

```
① 客观题（单选/多选/判断）本地程序判定，不进 LLM —— 省 Token
② 填空题先做精确 + 同义词表匹配，未命中再交 LLM
③ 主观题：LLM 按 rubric 逐点判定，输出命中/漏掉/答错 + 引用 chunk
④ 分数上限/下限做程序侧夹紧（防止 LLM 给负分或超满分）
⑤ 回写 bb_answer_item 与 bb_ai_call_log
```

| `/exam/:id` | **答题页** | 计时器、题目导航、打字 + 按住说话、自动存草稿、交卷确认 |
| `/exam/:id/result` | **判分结果页** | 逐题得分、命中/漏掉要点高亮、点击引用跳原文、申诉按钮 |
| `/mistake` | 错题本 | 筛选、按知识点聚合、手动移出 |
| `/review` | 复习模式 | 今日待复习队列，SM-2 驱动 |
| `/stat` | 统计 | 雷达图、趋势折线、成本报表 |
| `/interview` | **模拟面试首页** | 两个 Tab：简历库（上传/粘贴、解析进度、档案抽屉、重新解析）+ 面试记录（进度、得分、继续/看报告） |
| `/interview/:id/room` | **面试室** | 聊天式多轮问答：问题带题型与「依据简历哪一段」、回答实时显示五维得分、语音输入、提前结束 |
| `/interview/:id/report` | **面试评估报告** | 总分 + 维度雷达 + 逐轮曲线 + 薄弱项（带证据与建议）+ 薄弱知识点一键出题 + 完整对话回顾 |

> **新增一级路由时要同步那份白名单**，否则刷新会 404（`/kb`、`/interview` 都踩过这个坑）。

## 5. 前端技术约定

- **请求封装**：axios 实例统一处理 `code`、401 跳登录、`5031/5032` 展示友好降级提示。
- **SSE 封装**：`useTaskStream(taskId)` 组合式函数，自动重连、页面卸载时断连。
- **录音组件**：`<VoiceInput>` 统一封装"按住说话 → 上传 → 回填文本 → 可编辑"，全站复用（答题、复述、申诉理由都能用）。
- **富文本/公式**：代码题用 `highlight.js` 高亮，公式用 KaTeX（如果资料里有）。
- **状态**：Pinia 存当前知识库、当前厂商、用户偏好。
