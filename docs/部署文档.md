# 背备不悲 · 部署文档

> 目标：从一台干净的机器，到浏览器里能用。
>
> 全流程约 **40 分钟**，其中 25 分钟是下模型和装依赖。

---

## 0. 先搞清楚架构（这决定了你要装什么）

```
┌──────────────┐   HTTP / SSE    ┌──────────────────┐   HTTP / SSE   ┌──────────────────┐
│  beibei-web  │ ──────────────▶ │  beibei-server   │ ─────────────▶ │  beibei-agent    │
│  浏览器       │ ◀────────────── │  Spring Boot     │ ◀───────────── │  FastAPI         │
│  :8080       │                 │  :8080           │                │  :8000           │
└──────────────┘                 └────────┬─────────┘                └────────┬─────────┘
                                          │                                   │
                              ┌───────────┴───────────┐           ┌───────────┴───────────┐
                              │  MySQL 8  业务数据     │           │  Milvus   向量检索     │
                              │  :3306                │           │  :19530               │
                              └───────────────────────┘           └───────────────────────┘
                                                                  ┌───────────────────────┐
                                                                  │ 云端 API: LLM / ASR    │
                                                                  └───────────────────────┘
```

**关键点**

1. **前端构建产物由 Java 托管在同一个 8080 端口** —— 所以浏览器只需要访问一个地址，不存在跨域。
2. **Python 只在内网被 Java 调用**，浏览器永远不直连 8000。所以 8000 端口不需要对外开放。
3. **Java 不直连 Milvus**，向量检索全部由 Python 负责。
4. MySQL 和 Milvus 可以装在本机，也可以装在同一局域网的另一台机器/虚拟机上。

**三种部署形态**，按你的条件挑一种：

| 形态 | 适合 | 中间件放哪 |
|---|---|---|
| **A. 全本机** | 最省事，推荐先跑通 | Docker Desktop（Windows/Mac）或本机 Docker |
| **B. 本机跑代码 + 虚拟机跑中间件** | Windows 开发常见做法 | VMware/VirtualBox 里的 Linux + Docker |
| **C. 服务器部署** | 长期使用 | 一台 Linux 上全装 |

下面的步骤对三种形态都适用，只有「中间件地址」不同。

---

## 1. 硬件与系统要求

| 项 | 最低 | 推荐 | 说明 |
|---|---|---|---|
| 内存 | 8 GB | **16 GB+** | BGE-M3 推理约 2 GB，Milvus 约 1 GB，Java 约 0.5 GB |
| 磁盘 | 15 GB 空闲 | 30 GB+ | BGE-M3 权重 2.1 GB，PaddleOCR 约 0.5 GB，依赖约 3 GB |
| GPU | 不需要 | NVIDIA 8 GB+ | 有 GPU 向量化快 5~10 倍；没有也能跑（CPU 约 60 条/秒） |
| 系统 | Windows 10 / Linux / macOS | Windows 11 或 Ubuntu 22.04 | 开发机实测 Windows 11 |

> ⚠️ **磁盘空间要留意**：conda 环境、模型权重、上传资料都别放系统盘。
> 本文假设模型放 `D:/ai-models`，数据放 `D:/beibei-data`，你可以换成任何路径。

## 2. 装中间件（MySQL + Milvus）

### 2.1 用 Docker Compose 起（推荐）

新建一个目录，比如 `D:/beibei-docker`，放两个文件。

**MySQL** —— `docker-compose.yml`：

```yaml
services:
  mysql:
    image: mysql:8.0
    container_name: beibei-mysql
    restart: always
    environment:
      MYSQL_ROOT_PASSWORD: your-mysql-password   # ← 改成你自己的
      TZ: Asia/Shanghai
    command:
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_0900_ai_ci
      - --default-time-zone=+08:00
    ports:
      - "3306:3306"
    volumes:
      - ./volumes/mysql:/var/lib/mysql
```

**Milvus** —— 单独一个目录（比如 `D:/beibei-docker/milvus`），用官方 standalone compose：

```yaml
services:
  etcd:
    container_name: milvus-etcd
    image: quay.io/coreos/etcd:v3.5.18
    restart: always            # ← 官方模板没这行，一定要加，否则重启后 Milvus 不会自启
    environment:
      - ETCD_AUTO_COMPACTION_MODE=revision
      - ETCD_AUTO_COMPACTION_RETENTION=1000
      - ETCD_QUOTA_BACKEND_BYTES=4294967296
      - ETCD_SNAPSHOT_COUNT=50000
    volumes:
      - ./volumes/etcd:/etcd
    command: etcd -advertise-client-urls=http://etcd:2379 -listen-client-urls http://0.0.0.0:2379 --data-dir /etcd
    healthcheck:
      test: ["CMD", "etcdctl", "endpoint", "health"]
      interval: 30s
      timeout: 20s
      retries: 3

  minio:
    container_name: milvus-minio
    image: minio/minio:RELEASE.2024-05-28T17-19-04Z
    restart: always
    environment:
      MINIO_ACCESS_KEY: minioadmin
      MINIO_SECRET_KEY: minioadmin
    ports:
      - "9000:9000"
      - "9001:9001"
    volumes:
      - ./volumes/minio:/minio_data
    command: minio server /minio_data --console-address ":9001"
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:9000/minio/health/live"]
      interval: 30s
      timeout: 20s
      retries: 3

  standalone:
    container_name: milvus-standalone
    image: milvusdb/milvus:v2.5.23
    restart: always
    command: ["milvus", "run", "standalone"]
    security_opt:
      - seccomp:unconfined
    environment:
      MINIO_REGION: us-east-1
      ETCD_ENDPOINTS: etcd:2379
      MINIO_ADDRESS: minio:9000
    volumes:
      - ./volumes/milvus:/var/lib/milvus
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:9091/healthz"]
      interval: 30s
      start_period: 90s
      timeout: 20s
      retries: 3
    ports:
      - "19530:19530"
      - "9091:9091"
    depends_on:
      - "etcd"
      - "minio"

networks:
  default:
    name: milvus
```

起服务：

```bash
docker compose -f D:/beibei-docker/docker-compose.yml up -d      # MySQL
cd D:/beibei-docker/milvus && docker compose up -d                # Milvus
```

> **`restart: always` 别省。** 官方 Milvus compose 模板里没有这行，
> 结果是重启机器后 MySQL/Redis 都自己起来了、只有 Milvus 没起来，
> 表现为「昨天还好好的，今天向量库连不上」。这个坑我们踩过。

验证：

```bash
docker ps --filter name=beibei --filter name=milvus
# MySQL  :3306  可达
# Milvus :19530 可达
curl -s http://localhost:9091/healthz   # 应返回 OK
```

> **首次启动 Milvus 要等 30~90 秒**（它要先等 etcd 和 minio）。
> 这段时间 19530 连不上是正常的。

### 2.2 不想用 Docker？

MySQL 直接装原生版即可。Milvus **不提供原生 Windows 版**，只能用 Docker / WSL2，或者装在 Linux 机器上。所以「形态 B」其实就是这个原因。

## 3. 装 Python 环境

推荐用 conda 隔离环境（避免和系统 Python 打架）。

```bash
# 创建环境（Python 3.11）
conda create -n beibei python=3.11 -y
conda activate beibei

# 国内网络建议配镜像，否则装 torch 会非常慢
pip config set global.index-url https://mirrors.cloud.tencent.com/pypi/simple/
```

```bash
cd beibei-agent
pip install -r requirements.txt
```

> **关于 GPU 版 PyTorch**：`requirements.txt` 装的是 CPU 版 torch。
> 想用 GPU，去 [pytorch.org](https://pytorch.org/get-started/locally/) 按你的 CUDA 版本装对应的
> `torch`，然后把 `.env` 里的 `EMBEDDING_DEVICE` 改成 `cuda`。
> **不装 GPU 版也完全能用**，只是向量化慢一些（本项目实测 CPU 约 60 条/秒）。

### 3.1 下载模型权重

需要两个模型，都从 ModelScope 下（国内快）：

```bash
# BGE-M3 向量模型（约 2.1 GB）
pip install modelscope
python -c "
from modelscope import snapshot_download
snapshot_download('BAAI/bge-m3', cache_dir='D:/ai-models')
"
```

PaddleOCR 的权重**首次调用时自动下载**，不用手动下。

> ⚠️ **模型路径有讲究**：`.env` 里的 `EMBEDDING_MODEL` 填本地路径（如 `D:/ai-models/bge-m3`）或
> 模型名（如 `BAAI/bge-m3`）都行。Milvus 集合名按「模型名最后一段」推导：
> `BAAI/bge-m3` → `bb_chunk_bge_m3`。
> 所以**本地路径和模型名推导出的集合名一致**，互相切换不会丢数据。
>
> **但 embedding 模型一旦定了就不要换**：不同模型产出的向量空间不可比，
> 换了之后同一个知识库里新旧向量无法一起检索，RAG 直接失效。要换只能新建知识库重新入库。

### 3.2 装 ffmpeg（语音功能需要）

用于把浏览器录的 webm/opus 转成讯飞要求的 16k 单声道 PCM。

```bash
# Windows：直接下静态包解压，然后把路径填进 .env
# https://www.gyan.dev/ffmpeg/builds/  →  ffmpeg-release-essentials.zip
# 解压后把 bin/ffmpeg.exe 的完整路径填进 FFMPEG_PATH

# Ubuntu / Debian
sudo apt install -y ffmpeg
```

## 5. 配置密钥

### 5.1 Python 侧

```bash
cd beibei-agent
cp .env.example .env
```

打开 `.env` 逐项填：

```ini
# ---- 两个内部密钥：随便生成两串随机字符，两边必须一致 ----
INTERNAL_TOKEN=<随机串 1>
SECRET_KEY=<随机串 2>

# ---- 中间件地址 ----
MYSQL_HOST=192.168.1.100
MYSQL_PASSWORD=<你上面设的 MySQL 口令>
MILVUS_HOST=192.168.1.100

# ---- 模型路径 ----
EMBEDDING_MODEL=D:/ai-models/bge-m3
EMBEDDING_DEVICE=cuda        # 没有 GPU 就写 cpu

# ---- LLM：先用 Mock 把链路跑通，拿到 Key 再改 ----
LLM_MOCK=true

# ---- 语音（可留空，留空则录音按钮自动隐藏）----
XFYUN_APP_ID=
XFYUN_API_KEY=
XFYUN_API_SECRET=

# ---- 路径 ----
UPLOAD_DIR=D:/beibei-data/upload
FFMPEG_PATH=D:/tools/ffmpeg/bin/ffmpeg.exe
```

生成随机串：

```bash
python -c "import secrets; print(secrets.token_hex(24))"
```

> **这两个值用来干什么**
> - `INTERNAL_TOKEN`：Java 调 Python 时的身份校验，防止别人直接打你的 8000 端口
> - `SECRET_KEY`：给数据库里的 API Key 做 AES-256-GCM 加密用的口令
>
> **`SECRET_KEY` 改了会怎样**：数据库里已加密的 API Key 会解不开，需要去界面重新填一次。
> 所以定下来就别改。

### 5.2 Java 侧

`beibei-server/src/main/resources/application-dev.yml` 里改数据库连接：

```yaml
spring:
  datasource:
    url: jdbc:mysql://192.168.1.100:3306/beibei?...
    username: root
    password: "<你上面设的 MySQL 口令>"
```

`application.yml` 里的两个密钥**支持环境变量覆盖**，所以你可以不改文件：

```bash
# Windows PowerShell
$env:BEIBEI_INTERNAL_TOKEN="<随机串 1>"
$env:BEIBEI_SECRET_KEY="<随机串 2>"
```

也可以直接改文件（不推荐，容易误提交）：

```yaml
beibei:
  agent:
    internal-token: ${BEIBEI_INTERNAL_TOKEN:<你的随机串1>}
  security:
    secret: ${BEIBEI_SECRET_KEY:<你的随机串2>}
```

> ⚠️ **必须和 `beibei-agent/.env` 里的值完全一致**，否则 Java 调 Python 会 401。

另外改一下上传目录（默认是作者机器的路径）：

```yaml
beibei:
  upload:
    dir: D:/beibei-data/upload
  storage:
    backup-dir: D:/beibei-data/backup
```

## 7. 配置 AI 能力

### 7.1 大模型（必须，否则只能跑 Mock）

界面 → **设置 → AI 配置** → 新增厂商：

| 厂商 | Base URL | 模型名 | 备注 |
|---|---|---|---|
| DeepSeek | `https://api.deepseek.com` | `deepseek-chat` | 便宜，中文好，推荐入门 |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` | |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-plus` | |
| 月之暗面 | `https://api.moonshot.cn` | `moonshot-v1-8k` | |
| OpenAI | `https://api.openai.com` | `gpt-4o-mini` | |
| 本地 Ollama | `http://127.0.0.1:11434` | `qwen2.5:7b` | 全离线 |

填好 API Key → 点**「测试连通」**（会真的发一条最小请求验证 Key 有效）→ 打开**「启用」**。

然后改 `beibei-agent/.env`：

```ini
LLM_MOCK=false
```

**重启 beibei-agent**（Prompt 与厂商配置都有进程内缓存，不重启不生效）。

> 🔴 **`LLM_MOCK` 是最容易被忽略的一个开关。**
>
> 症状特别好认：AI 能跑通、也不报错，但**输出很粗浅**——
> 出题永远是同义改写；模拟面试永远问「你简历里写了 X，说说怎么用」，
> 不会顺着你的回答追问；评分每轮都差不多。
>
> 觉得「AI 好像不太聪明」时，**先看一眼这个开关**，
> 再看自检里显示的模型名（Mock 模式会显示成 `mock-llm`）。

### 7.2 语音识别（可选）

只支持讯飞**语音听写（流式版）**，因为它和别的厂商协议不一样。

**开通步骤**

1. 打开 <https://console.xfyun.cn/app/myapp>，注册并**实名认证**
2. 「创建应用」→ 平台选 **WebAPI**
3. 进应用 → 左侧找 **「语音听写（流式版）」** → 领取免费额度（**默认每日 500 次**，自用够）
4. 拿到三个值：**APPID**、**APIKey**、**APISecret**

**填在哪**

界面 → 设置 → AI 配置 → 编辑「讯飞语音听写」，三栏都填 → 打开「启用」。
（这个页面填完**不用重启**，保存即生效。）

**注意讯飞要三个值，不是「一个 API Key」**：握手签名是
`hmac-sha256(host+date+request-line, APISecret)`，再和 APIKey 一起 base64 成 `authorization`。
**只给 APIKey 连签名都算不出来。**

**服务端点**（下拉选择，别手输）：

| 场景 | 地址 |
|---|---|
| 中英文（推荐） | `wss://iat-api.xfyun.cn/v2/iat` |
| 中英文（备用） | `wss://ws-api.xfyun.cn/v2/iat` |
| 小语种 | `wss://iat-niche-api.xfyun.cn/v2/iat` |

> 讯飞官方文档把地址写成 `ws[s]://...`（表示 ws 或 wss），
> **别连方括号一起复制**，否则会报 `Illegal character in scheme name`。

**验证**

```bash
python scripts/test_asr.py
```

这个脚本用系统 TTS 合成一句已知的话，走完整链路识别回来对比，会打印相似度和关键词命中率。

## 8. 第一次使用：走一遍完整流程

```
1. 知识库页 → 新建知识库
2. 进知识库 → 上传资料（PDF / Word / 照片都行）
3. 等解析完成（SSE 会显示进度；首次会加载模型，慢一点）
4. 知识点页 → 看 AI 抽的知识点树，不满意可以改
5. AI 出题 → 选 10 道 → 生成 → 进审核页逐题过一遍 → 通过
6. 开始答题 → 打字或用语音（长按空格）
7. 交卷 → 看判分结果（命中/遗漏要点 + 原文引用）
8. 错题本 / 复习计划 → 按计划复习
9. 模拟面试 → 上传简历 → 开始面试 → 看报告 → 一键生成专项题卷
```

## 9. 常见问题

### 启动类

**Q：`JAVA_HOME` 报错，或者编译报「非法字符: '\ufeff'」**
BOM 问题。用编辑器把文件另存为「UTF-8 无 BOM」。
PowerShell 写文件时要显式用 `New-Object System.Text.UTF8Encoding($false)`，默认会带 BOM。

**Q：`mvn package` 报 `Unable to rename ... .jar.original`**
jar 被正在运行的 JVM 锁住了。先停掉服务再打包。

**Q：前端 `npm run build` 报 `TS6310: Referenced project may not disable emit`**
`tsconfig.node.json` 里同时有 `composite: true` 和 `noEmit: true` 是非法组合。
本仓库已修（改成 `emitDeclarationOnly` + `outDir` 指向 `node_modules/.tmp`）。如果你是老版本，照这个改。

**Q：`npm` 命令被执行策略拦截（PowerShell）**
用 `npm.cmd` 代替 `npm`。

### 数据库 / 向量库类

**Q：解析成功但检索召回 0 条**
Milvus 默认一致性是 Bounded，刚写入的数据查不到。本项目已在入库后 `flush()`、
检索时用 `consistency_level="Strong"`。如果你自己写代码接 Milvus，注意这一点。

**Q：写入报 `partition not found[kb_2]`**
分区没建出来。注意 `list_partitions()` 返回的是 `List[str]` 而不是 `List[dict]`，
按文档写 `p["name"]` 会静默抛异常（被 except 吞掉），分区永远建不出来。

**Q：删知识库报 `partition cannot be dropped, partition is loaded`**
先 `release_partitions()` 再 `drop_partition()`。

**Q：删了文档，向量还在（检索能搜到已删除的内容）**
Milvus 删除是异步的，且默认一致性看不到刚删的数据。
项目里有 `/api/sys/consistency-check` 做双向校验与清理，界面上「系统设置」也能点。

**Q：自检显示 `24/21 张表`**
期望表数常量没更新。本仓库已修。

### 模型 / 性能类

**Q：首次向量化特别慢**
要加载 2.1 GB 模型，等十几秒到一分钟正常。之后每条几十毫秒。

**Q：向量化还是慢**
- 确认 `EMBEDDING_DEVICE` 和实际一致（有 GPU 写 `cuda`）
- 项目已做两处优化：**按长度排序后再分 batch**（减少 padding 浪费）、
  **把 `max_seq_length` 从 8192 限制到 1024**（分块目标只有 700 token）。
  实测这两项让单批耗时从 231 秒降到 91 秒。

**Q：`ModuleNotFoundError: No module named 'paramiko'`**
`scripts/vm_ssh.py` 的依赖，只在用「虚拟机跑中间件」这种形态时才需要。
`pip install paramiko`。

### 网络 / 下载类

**Q：装 torch 特别慢**
换镜像。实测：腾讯云 PyPI **44 MB/s**，阿里云对 torch 这类大包只有 **0.07 MB/s**，
清华源可能 403，GitHub 基本不可用。

```bash
pip config set global.index-url https://mirrors.cloud.tencent.com/pypi/simple/
```

**Q：CUDA 版 torch 下不动**
国内没有可靠的快镜像（实测阿里云 0.09 MB/s，装完要 7.7 小时）。
**建议直接用 CPU 版**，本项目 CPU 实测约 60 条/秒，日常够用。

### 功能类

**Q：界面改了没生效 / 浏览器还在跑旧版本**
项目已把静态资源设为 `Cache-Control: no-cache`。如果你改过配置，
注意：**`index.html` 不要设长缓存**，否则构建后浏览器还引用已删除的旧 chunk，页面直接白屏。
实在不行按 **Ctrl + F5** 强制刷新。

**Q：AI 输出很粗浅 / 面试提问很模板化**
看 `LLM_MOCK` 是不是 `true`。见 7.1 节。

**Q：录完音提示「没有拾到声音」**
录到的音频电平接近 0，是采集端问题，不是程序问题。依次检查：
1. 系统声音设置里的**输入设备**选对了吗，对着说话看音量条动不动
2. 麦克风有没有被物理静音 / 笔记本静音键
3. 系统隐私设置是否允许桌面应用访问麦克风
4. 浏览器地址栏左侧权限图标里麦克风是否「允许」
5. 插着蓝牙耳机时，浏览器可能选了耳机麦克风，换内置麦克风试试

后端日志会写明用的是哪个设备：`音频电平：RMS=0.0 ... · 麦克风=<设备名>`。

**Q：报 `Illegal character in scheme name at index 2: ws%5Bs%5D://...`**
把讯飞文档里的 `ws[s]://` 简写连方括号一起复制进去了。改成 `wss://`。

**Q：语音识别结果里有错字**
项目有专有名词热词纠错（从知识库知识点构建热词表）。
如果某个术语老是被纠错，可以在「AI 配置」页的 Prompt 模板里调整，或去知识点页把该术语加成知识点。

### 安全类

**Q：API Key 存在哪里？安全吗？**
存 MySQL 的 `bb_ai_provider.api_key_enc`，用 **AES-256-GCM** 加密，
密钥是 `SECRET_KEY` 的 SHA-256。接口返回时一律脱敏（只回「是否已配置」和掩码）。
**但这不是银弹**：`SECRET_KEY` 也在同一台机器上，所以它防的是「误看到数据库内容」，不是「机器被攻破」。

**Q：要暴露到公网吗？**
这个项目**是单用户本地设计，没有账号体系、没有鉴权**。**不要直接暴露到公网。**
真要远程访问，加一层带认证的反向代理（Nginx + Basic Auth / Authelia 之类），
并且只暴露 8080，**不要**暴露 8000 和 3306。

去「系统设置 → 一致性校验」看看，必要时重新解析文档。

### Milvus 开机自启（Linux 中间件机）

如果 Milvus 用 compose 起，**记得加 `restart: always`**（见 2.1）。想更稳可以再加 systemd 单元：

```ini
# /etc/systemd/system/milvus.service
[Unit]
Description=Milvus standalone (docker compose)
Requires=docker.service
After=docker.service network-online.target
Wants=network-online.target

[Service]
Type=oneshot
RemainAfterExit=yes
WorkingDirectory=/opt/milvus          # 改成你的 compose 目录
ExecStart=/usr/bin/docker compose up -d
ExecStop=/usr/bin/docker compose stop
TimeoutStartSec=0

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now milvus
```

> 比只靠 `restart: always` 强的地方是**保证 etcd → minio → standalone 的启动顺序**
> （`compose up` 会读 `depends_on`，而 restart 策略是三个容器同时被拉起、没有顺序）。
